# 省 Token 协议

> 加载本技能本身也要花 token。只在确实要读大文件、抓长网页或做多轮工具调用时加载它。
> 一句话版本：**先想清楚信息是不是非拿不可，再想能不能只拿一小段。**

## 先看 token 花在哪

每一次模型调用都要**重新发送**：系统提示词 + 全部工具的 JSON Schema + 记忆窗口里的全部历史 + 本轮新增的工具结果。所以总消耗约等于：

```
(固定开销 × 模型轮数) + 累计工具结果 + 累计历史
```

三条推论，也就是下面规则的优先级：**减少轮数** > **缩小工具结果** > **把回答写短**。

## 一、工具调用：先便宜，后昂贵

1. **先看目录再读文件**。用 `list_files` 确认路径存在，不要靠猜路径试错——每一次失败的工具调用，都是一轮完整的模型调用。
2. **`read_file` 一律分页**。它默认一次带回 500 行、硬上限 5000 行，整段都会留在上下文里。先用 `startLine` + `maxLines`（建议 40～80 行）定位，再按需扩大范围。
3. **不要为了找一处改动而通读整个文件**，先定位再精读。
4. **`http_fetch` 只抓真正需要的地址**。单次最多返回 20000 字符且整段进入上下文，同一个 URL 不要重复抓。
5. **互不依赖的调用合并到同一轮发出**，把 N 轮压缩成 1 轮。
6. **够了就停**。信息足以回答时立刻给最终答案，不要"再确认一下"。

## 二、工具结果：进入上下文前先瘦身

- 读到大段内容后，先在内部把它压成 **结论 + 关键数据 + 出处**，后续推理只使用压缩版。
- 丢掉与当前子问题无关的行：日志噪音、重复堆栈、样板文本、页面导航。
- 大 JSON / 表格只保留这次真正用到的字段和行。

## 三、绝不重复读取

- 维护一张"已读清单"：`路径 + 行段 + 已得到的结论`。
- 同一文件的同一行段**不读第二遍**；需要时直接引用已有结论。
- 只有内容确实变了（例如刚 `write_file` 写过）才重新读取。

## 四、输出也要省

- 不复述用户的问题，不长篇预告"我准备做什么"。
- 最终答案用要点或表格，不写与问题无关的背景知识。
- **不要把工具返回的原文整段贴回答案**，只给提炼后的结果。

## 五、大任务：分而治之

- 拆成"一次只处理一个文件 / 一段"的小步，每次只把当前片段放进上下文。
- 中间产物用 `write_file` 落盘，之后用分页 `read_file` 按需取回，不要一直堆在对话历史里。
- 长文档总结时逐段处理并累加要点，而不是把全文读进来再总结。

## 六、配置侧的一次性收益

| 配置 | 作用 |
|---|---|
| `myclaw.memory.max-messages` | 限制历史条数（如 20～40），框架会自动修复被裁断的 tool_calls 配对 |
| `myclaw.max-iterations` | 兜底，防止工具调用死循环持续烧 token |
| `myclaw.max-tokens` | 限制单次输出长度 |
| `myclaw.tools.*` | **只开启真正需要的工具**：每个工具的 Schema 每轮都会重发 |
| `myclaw.skills.enabled` | 技能正文只在 `load_skill` 时展开，保持按需加载 |

确定性的算术交给 `calculate` 等工具，不要让模型"心算"之后再长篇输出过程。

## 自检：每次准备调用工具前问三句

1. 这个信息我**已经有了**吗？
2. 能用**更小的范围**取到吗？
3. **够回答了吗**？够就停下并作答。
